# Stronghold v1.0.0 Release Notes

**Release Date:** 2026-07-29

## Overview

Stronghold v1.0.0 is the first release of a self-hosted gateway that lets AI agents request, attach to, and work inside isolated containerd workspaces on a fleet of Vultr boxes — with phone-approved sessions (WebAuthn, no custom phone app), post-quantum cryptography end-to-end, SEV-SNP confidential computing, and multi-tenancy from day one.

## Features

### Agent Protocol
- ORDER / RESUME / RELEASE / EXTEND endpoints
- Machine lifetime decoupled from agent connection (TTL-based)
- Full PTY access via WebSocket proxy
- Quorum re-approval for destructive operations

### Security
- **Post-Quantum Transport:** TLS 1.3 + X25519MLKEM768 hybrid key exchange
- **Dual-Signed Audit Log:** Ed25519 signatures (ML-DSA-65 deferred — crate unstable)
- **E2E Push Encryption:** X25519 + ML-KEM-768 hybrid KEM → HKDF-256 → AES-256-GCM
- **WebAuthn Session Approval:** Phishing-resistant, biometric-verified, multi-credential
- **SEV-SNP Attestation:** Gateway runs in AMD SEV-SNP confidential VM with key sealing
- **No External Providers:** Self-hosted ntfy, APNs/FCM wake-up only

### Multi-Tenancy
- Per-tenant credentials, quotas, audit logs
- Tenant isolation at the database layer (tenant_id on every table)
- Per-tenant network policies and egress allowlists

### Image Catalog
- 8 pre-built images, all extending from `stronghold/rocky-base`
- `image.toml` DSL for declarative image definitions
- Containerfile generation with escape hatches

### Infrastructure
- k3s worker plane (single-box or multi-box fleet)
- Vultr VPS escalation for GPU/large-memory workloads
- Self-hosted ntfy for push notifications

## Known Issues

1. **ML-DSA-65 deferred** — ml-dsa crate unstable, Ed25519-only for v1.0
2. **WebAuthn PQC gap** — FIDO PQC authenticators not deployed (~2027)
3. **SEV-SNP untested on real hardware** — dev box lacks /dev/sev
4. **PTY proxy stub** — k3s exec WebSocket deferred
5. **Self-signed cert generation** — uses external PEM files for now
