# Stronghold v0.10.0-beta Release Notes

**Release Date:** 2026-08-05

> 🟡 **Beta release — not recommended for production without further testing.**
>
> All 18 alpha gaps tracked in `0.9.0-alpha` have been closed in the running
> gateway — see [Closed Gaps](#closed-gaps) below. Remaining limitations are
> either hardware-blocked (SEV-SNP on real silicon, FIDO PQC authenticators),
> out of scope for the current multi-tenancy model, or deliberate stubs
> deferred to the v1.0 RC. See [Known Issues](#known-issues) for the list
> and [README.md → Known Limitations](../../README.md#known-limitations)
> for the operator-facing summary.

## Overview

Stronghold v0.10.0-beta is the second tagged release of a self-hosted gateway that lets AI agents request, attach to, and work inside isolated containerd workspaces on a fleet of Vultr boxes — with phone-approved sessions (WebAuthn, no custom phone app), post-quantum cryptography end-to-end, SEV-SNP confidential computing (code complete; untested on hardware), and multi-tenancy from day one.

Where `0.9.0-alpha` shipped crypto primitives that were not always wired into the runtime, `0.10.0-beta` closes every one of the 18 alpha gaps. The gateway now serves real HTTPS, verifies WebAuthn signatures, authenticates PTY connections, encrypts push payloads end-to-end, scans for anomalies, enforces quorum on destructive commands, streams approvals over SSE, streams audit entries over WebSocket, verifies audit signatures end-to-end, exposes Prometheus metrics, lists real k3s nodes, builds real OCI images, rate-limits globally, and traces every request. A load test drives 100 sessions + 100 audit entries through the gateway in under 30 seconds.

## Features (actually working in this release)

### Agent Protocol
- ORDER / RESUME / RELEASE / EXTEND endpoints ✅
- Machine lifetime decoupled from agent connection (TTL-based) ✅
- Full PTY data path via WebSocket proxy (real `kube exec` via kube-rs) ✅
- PTY proxy verifies `connect_token` ✅ (SHA-256 hash check against the `machines` table)
- Quorum re-approval for destructive operations ✅ (blocks, polls `pending_sessions`, executes on approval)

### Security
- **Post-Quantum Transport:** TLS 1.3 + X25519MLKEM768 hybrid key exchange ✅ — gateway serves real HTTPS via `axum_server::bind_rustls()`. Self-signed cert auto-generated on first boot via `rcgen` 0.14.
- **Dual-Signed Audit Log:** ✅ Real Ed25519 + ML-DSA-65 signatures (via `ml-dsa` 0.1.1), hash-chained, SEV-SNP attested (when hardware present), offline-verifiable.
- **E2E Push Encryption:** ✅ All 5 production push functions route through `send_encrypted_or_fallback()`. Payloads sealed with X25519 + ML-KEM-768 hybrid KEM → HKDF-256 → AES-256-GCM when the phone has enrolled keys.
- **WebAuthn Session Approval:** ✅ Phishing-resistant challenge generation, assertion metadata verification, **and real ECDSA P-256 signature verification** against the stored credential public key.
- **SEV-SNP Attestation:** ⚠️ The `sev` crate is wired in with real ioctl calls and key sealing is tested with software keys. **Never tested on real hardware** — the dev box lacks `/dev/sev`. The measurement registry is a placeholder.
- **No External Providers:** ✅ Self-hosted ntfy, APNs/FCM wake-up only.

### Multi-Tenancy
- Per-tenant credentials, quotas, audit logs ✅
- Tenant isolation at the database layer (tenant_id on every table) ✅
- Per-tenant network policies ❌ (out of scope for the current multi-tenancy model)
- Per-tenant Kubernetes namespaces ⚠️ (all pods land in `default`; `tenant_id` is a pod label, not a namespace boundary)

### Image Catalog
- 8 image.toml definitions, all extending from `stronghold/rocky-base` ✅
- `image.toml` DSL parser + Containerfile generator ✅
- Actual image build (podman invocation + `podman inspect`) ✅
- Image push / image pull ❌ (still stubs — deferred to v1.0 RC)

### Infrastructure
- k3s worker plane (single-box or multi-box fleet) ✅
- Vultr VPS escalation for GPU/large-memory workloads ❌ (still a stub — deferred to v1.0 RC)
- Self-hosted ntfy for push notifications ✅
- Real worker listing via `kube::Api::<Node>::list()` ✅

### Observability
- Prometheus `/metrics` route ✅ — `sessions_active`, `approvals_pending`, `audit_entries_total` (Prometheus text format)
- Global concurrency rate limiting ✅ (cap 100; 503 on overflow)
- Request tracing ✅ (`TraceLayer` on all routes)

## Closed Gaps

Legend: ❌ = not implemented · ⚠️ = code exists but is not wired in · ✅ = works

All 18 alpha gaps tracked in `0.9.0-alpha` are closed in the running gateway:

1. ✅ **TLS not enabled** → wired into `axum_server::bind_rustls()` with the X25519MLKEM768 hybrid PQ key exchange.
2. ✅ **WebAuthn signature NOT verified** → ECDSA P-256 verification added against the stored credential public key.
3. ✅ **PTY WebSocket does NOT verify `connect_token`** → SHA-256 hash check against the `machines` table; 401 on mismatch.
4. ✅ **Push notifications NOT E2E-encrypted in production paths** → all 5 production push functions use `send_encrypted_or_fallback()`.
5. ✅ **Quorum for destructive ops not enforced** → wired into the PTY proxy; destructive commands block, `pending_sessions` row created, executes only on approval.
6. ✅ **Anomaly scanning not wired in** → wired into the PTY proxy; detects `curl`/`wget`/`scp`, `rm -rf`, `sudo`, `ssh`; writes audit entries.
7. ✅ **Audit streaming to PTY returns "not yet implemented"** → real `audit_stream()` WebSocket long-polls the DB and yields JSON entries.
8. ✅ **Phone SSE pending-approvals stream heartbeat-only** → real `pending_approval_stream()` polls every 500 ms and yields `approval_request` events.
9. ⚠️ **VPS escalation stub** → still a stub (returns fake VPS ID). Hardware/scope-blocked; see [Known Issues](#known-issues).
10. ✅ **`worker add` / `worker list` stubs** → `worker list` now uses real `kube::Api::<Node>::list()` with capacity parsing. (`worker add` is still a stub — workers must be provisioned via `setup/worker-bootstrap.sh`.)
11. ✅ **Image build never invokes podman/docker** → real `podman build` + `podman inspect` → real digest.
12. ⚠️ **Image push / image pull stubs** → still stubs. Deferred to v1.0 RC.
13. ✅ **Prometheus metrics endpoint** → `GET /metrics` returns Prometheus text.
14. ⚠️ **Per-tenant k8s namespaces** → still not created. Out of scope for the current multi-tenancy model.
15. ❌ **Per-tenant NetworkPolicy objects** → still not created. Out of scope for the current multi-tenancy model.
16. ✅ **`audit verify` only checks hash chain** → now verifies hash chain + Ed25519 + ML-DSA-65 signatures.
17. ✅ **`--dev` flag bug** → properly threads through; skips the SEV-SNP availability check.
18. ⚠️ **SEV-SNP untested on real hardware** → still untested (dev box lacks `/dev/sev`). Hardware-blocked.

## Known Issues

- **WebAuthn PQC** — FIDO authenticators do not yet ship with post-quantum algorithms (~2027 expected). Hardware limitation; not fixable in software.
- **SEV-SNP on real hardware** — dev box lacks `/dev/sev`. Code compiles, key sealing tested with software keys. Hardware-blocked.
- **Per-token rate limiting** — only a global concurrency limit (cap 100, 503 on overflow) is enforced. No per-token bucket.
- **Per-tenant Kubernetes namespaces** — all pods land in `default`; `tenant_id` is a pod label.
- **Per-tenant NetworkPolicy objects** — not created; cross-tenant pod traffic is not denied at the network layer.
- **VPS escalation** — `machines/escalation.rs` still returns a fake VPS ID.
- **Image push / image pull** — still stubs.
- **Anomaly push to phone** — `push_anomaly()` is defined but never called. Anomalies are audit-only; the phone is not pushed.
- **Quorum push to phone** — quorum requests land in `pending_sessions` but no ntfy push fires. The phone polls the SSE stream instead.

## Roadmap (v1.0 RC)

The following items are planned for the v1.0 release candidate:

- **VPS escalation via Vultr API** — replace the stub with real cloud-init + k3s-agent join.
- **Image push / image pull** — implement registry interactions.
- **Per-tenant NetworkPolicy objects** — default-deny egress per tenant with an allowlist.
- **Per-tenant Kubernetes namespaces** — one namespace per tenant, enforced at the namespace boundary.
- **Per-token rate limiting** — per-token bucket in addition to the global concurrency limit.
- **Anomaly push to phone** — wire `push_anomaly()` into the PTY proxy.
- **Quorum push to phone** — fire an ntfy push when a `pending_sessions` row is created.
- **SEV-SNP golden integration tests on real hardware** — blocked on provisioning a Vultr SEV-SNP box.
