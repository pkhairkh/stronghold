# Stronghold v0.9.0-alpha Release Notes

**Release Date:** 2026-07-29

> ⚠️ **ALPHA RELEASE — DO NOT DEPLOY IN PRODUCTION** ⚠️
>
> This is an alpha release. Several advertised security features are NOT
> enforced by the running gateway (TLS, WebAuthn signature verification,
> quorum, anomaly scanning, E2E push encryption in production paths,
> per-tenant network policies, SEV-SNP on real hardware). See
> [Known Open Gaps](#known-open-gaps) below for the exhaustive list and
> [README.md → Known Limitations](../../README.md#known-limitations) for
> the operator-facing summary.

## Overview

Stronghold v0.9.0-alpha is the first tagged release of a self-hosted gateway that lets AI agents request, attach to, and work inside isolated containerd workspaces on a fleet of Vultr boxes — with phone-approved sessions (WebAuthn, no custom phone app), post-quantum cryptography end-to-end (primitives implemented; not all wired into the runtime — see gaps), SEV-SNP confidential computing (code complete; untested on hardware), and multi-tenancy from day one.

This was previously tagged internally as `v1.0.0`. An audit found that the docs overstate the implementation status: several security-critical features are implemented as code but are not enforced by the running gateway. The release has been **renamed to `0.9.0-alpha`** to reflect actual maturity, and this document has been corrected accordingly.

## Features (actually working in this release)

### Agent Protocol
- ORDER / RESUME / RELEASE / EXTEND endpoints ✅
- Machine lifetime decoupled from agent connection (TTL-based) ✅
- Full PTY data path via WebSocket proxy (real `kube exec` via kube-rs) ✅
- PTY proxy verifies `connect_token` ❌ (gap #3)
- Quorum re-approval for destructive operations ❌ (gap #5 — moved to [Roadmap](#roadmap))

### Security
- **Post-Quantum Transport:** TLS 1.3 + X25519MLKEM768 hybrid key exchange — ⚠️ code complete in `crypto/tls.rs` but **NOT wired into server startup**. `main.rs::serve()` binds a plain TCP listener; TLS config is computed and discarded.
- **Dual-Signed Audit Log:** ✅ Real Ed25519 + ML-DSA-65 signatures (via `ml-dsa` 0.1.1), hash-chained, SEV-SNP attested (when hardware present), offline-verifiable.
- **E2E Push Encryption:** ⚠️ X25519 + ML-KEM-768 hybrid KEM → HKDF-256 → AES-256-GCM primitives are implemented. **Only the test-only `send_encrypted_notification_to()` uses them.** All production push paths send plaintext (gap #4).
- **WebAuthn Session Approval:** ⚠️ Phishing-resistant challenge generation and assertion **metadata** verification (challenge / origin / UV flag / RP ID hash). **The cryptographic signature is NOT verified** (gap #2).
- **SEV-SNP Attestation:** ⚠️ Gateway can run inside an AMD SEV-SNP confidential VM with key sealing. The `sev` crate is wired in with real ioctl calls. **Never tested on real hardware** (gap #18); the measurement registry is a placeholder.
- **No External Providers:** ✅ Self-hosted ntfy, APNs/FCM wake-up only.

### Multi-Tenancy
- Per-tenant credentials, quotas, audit logs ✅
- Tenant isolation at the database layer (tenant_id on every table) ✅
- Per-tenant network policies ❌ (gap #15 — moved to [Roadmap](#roadmap))
- Per-tenant Kubernetes namespaces ❌ (gap #14 — all pods land in `default`; `tenant_id` is only a label)

### Image Catalog
- 8 image.toml definitions, all extending from `stronghold/rocky-base` ✅
- `image.toml` DSL parser + Containerfile generator ✅
- Actual image build (podman/docker invocation) ❌ (gap #11)
- Image push / image pull ❌ (gap #12)

### Infrastructure
- k3s worker plane (single-box or multi-box fleet) ✅
- Vultr VPS escalation for GPU/large-memory workloads ❌ (stub — gap #9)
- Self-hosted ntfy for push notifications ✅

4. ⚠️ Push notifications NOT E2E-encrypted in production paths.
5. ❌ Quorum for destructive ops — not enforced (see Roadmap).
6. ❌ Anomaly scanning — not wired into the PTY proxy.
7. ❌ Audit streaming to PTY — `audit_stream()` returns "not yet implemented".
8. ⚠️ Phone SSE pending-approvals stream — heartbeat-only, no real events.
9. ❌ VPS escalation — stub.
10. ❌ `worker add` / `worker list` — stubs.
11. ❌ Image build — generates Containerfile, never calls podman/docker.
12. ❌ Image push / image pull — stubs.
13. ❌ Prometheus metrics — no `/metrics` route.
14. ❌ Per-tenant k8s namespaces — all pods in `default`.

17. ❌ `--dev` flag — sets a struct field, not `STRONGHOLD_DEV`; does not bypass SEV-SNP check. Use `STRONGHOLD_DEV=1`.

## Previously listed gaps (subset closed)

- ~~ML-DSA-65 deferred~~ — **CLOSED**: Real ML-DSA-65 signatures implemented using `ml-dsa` 0.1.1 crate. Audit log is now truly dual-signed (Ed25519 + ML-DSA-65). Backward compatible: legacy Ed25519-only entries still verify.
- ~~PTY proxy stub~~ — **CLOSED (data path only)**: Real k8s exec via kube-rs WebSocket. `open_pty()` opens an exec session with stdin/stdout/stderr/tty, pumps bytes bidirectionally via mpsc channels. Verified end-to-end with a real pod on the dev box. *Note: connect_token verification is still missing — see gap #3.*
- ~~Self-signed cert generation~~ — **PARTIALLY CLOSED**: `generate_self_signed_cert()` uses `rcgen` 0.14 to create ECDSA P-256 self-signed certs with 10-year validity. `generate_self_signed_cert_files()` writes tls.crt (0644) + tls.key (0600). **The function exists and is unit-tested, but it is NOT wired into server startup.** `serve()` does not load the cert. See gap #1.

## Roadmap

The following items are **planned but not yet implemented** as of `0.9.0-alpha`. They were previously listed as features; they have been moved here for accuracy.

- **Quorum re-approval for destructive operations.** Data structures exist in `sessions/scopes.rs`. The PTY proxy needs to scan commands, classify destructive ops, and block on multi-credential re-approval.
- **Per-tenant network policies.** No `NetworkPolicy` objects are created. Planned: default-deny egress per tenant with an allowlist (github.com, crates.io, etc.).
- **Per-tenant Kubernetes namespaces.** All pods currently land in `default`. Planned: one namespace per tenant, with `tenant_id` enforced at the namespace boundary.
- **TLS termination in `serve()`.** Wire the existing `crypto/tls.rs` config into `axum_server::accept_rustls()` (or equivalent), load `tls.crt`/`tls.key` from `/etc/stronghold/keys/`, and gate behind a feature flag for dev.
- **WebAuthn signature verification.** Use `webauthn-rs` to verify the COSE ES256/RS256/Ed25519 signature, not just the assertion metadata.
- **PTY WebSocket `connect_token` verification.** Add an auth check in the PTY WS upgrade handler.
- **Anomaly scanning wired into the PTY proxy.** Instantiate `anomaly::Scanner` per session and scan PTY bytes.
- **Audit streaming to PTY WebSocket.** Implement `routes/pty.rs::audit_stream()`.
- **Phone SSE approval events.** Make `sessions/manager.rs::pending_approval_stream()` emit real approval-request events, not just heartbeats.
- **E2E-encrypted push notifications in production paths.** Route all push sends through `send_encrypted_notification_to()`.
- **VPS escalation via Vultr API.** Replace the stub with real cloud-init + k3s-agent join.
- **`worker add` / `worker list`.** Implement real SSH/cloud-init provisioning and a real worker registry.
- **Image build via podman/docker.** Invoke the build tool after Containerfile generation.
- **Image push / image pull.** Implement registry interactions.
- **Prometheus `/metrics` route.** Expose `stronghold_sessions_active`, `stronghold_approvals_pending`, etc.
- **`audit verify` signature check.** Verify Ed25519 + ML-DSA-65 signatures, not just the hash chain.
- **`--dev` flag fix.** Set `STRONGHOLD_DEV=1` env var (or change `serve()` to read the struct field).
- **SEV-SNP golden integration tests on real hardware.** Blocked on provisioning a Vultr SEV-SNP box.
