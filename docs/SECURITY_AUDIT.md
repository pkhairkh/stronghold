## Findings

### 1. `unwrap()` in production code — LOW severity

**Location:** `gateway/src/routes/metrics.rs:18`
```rust
let conn = state.db.get().unwrap();
```

**Risk:** If the DB pool is exhausted, this will panic and crash the gateway process. The `/metrics` endpoint is not user-facing (typically scraped by Prometheus), so the risk is limited to availability.

**Fix:** Replaced with proper error handling that returns HTTP 500 on pool exhaustion.

### 2. `expect()` in test code — NOT a finding

All `.expect()` calls are in `#[cfg(test)]` modules or test functions. This is acceptable — tests should panic on unexpected states.

### 3. SQL injection — NOT a finding

All SQL queries in the codebase use `rusqlite::params![]` for parameterization. No `format!` or string concatenation is used for SQL values. Verified by grepping for `format!` near `execute`/`query` calls — zero hits.

### 4. Command injection — NOT a finding

The only `Command::new` calls are in `images/builder.rs` for podman:
- `podman build -t <tag> -f <containerfile_path> .`
- `podman inspect --format {{.Digest}} <tag>`

The `tag` parameter comes from the CLI/API and is passed as a separate argument (not interpolated into a shell string). Podman itself handles argument parsing. The `containerfile_path` is a temp directory path generated by `tempfile::tempdir()` — not user-controlled.

However, if a malicious `tag` contains shell metacharacters, podman might interpret them. The fix would be to validate `tag` as a valid OCI reference. This is a LOW risk since only authenticated tenants can call `image build`.

### 5. `unsafe` blocks — NOT a finding

Zero `unsafe` blocks in the codebase. The previous `unsafe` transmutation for ML-DSA-65 key conversion was removed in favor of the `Into` trait.

## Recommendations

1. **Install cargo-audit on the dev box** and add it to CI: `cargo install cargo-audit && cargo audit`
2. **Add cargo-deny** for license compliance checking
3. **Validate OCI image tags** before passing to podman (reject tags with shell metacharacters)
4. **Add request body size limits** to prevent DoS via large POST bodies
5. **Add connection timeout** to the WebSocket PTY proxy to prevent resource exhaustion
